# راهنمای نصب و نگهداری سامانه فاکتور

این راهنما برای مالک سامانه است. نسخه برنامه از `VERSION` و `/api/info` خوانده
می‌شود؛ نسخه هیدیفای و نسخه افزونه دو مقدار جدا هستند. پشتیبانی پنل در حال حاضر
دقیقاً برای **۱۲.۰.۰ و ۱۴.۲.۰** است، نه تمام نسخه‌های ۱۲ یا ۱۴.

## چه چیزی کجا نصب می‌شود؟

| بخش | محل نصب | وظیفه |
|---|---|---|
| سامانه فاکتور | یک سرور مرکزی مستقل | پنل وب، دیتابیس، زمان‌بند، بات اصلی و بات‌های فروشگاهی |
| افزونه هیدیفای | هر سرور اصلی دارای Hiddify Panel | قفل و پاک‌کردن رمز ورود نماینده با API مالک |
| سرور میانی | مسیر شبکه میان دامنه و سرور اصلی، در صورت نیاز | انتقال ارتباط؛ افزونه روی آن لازم نیست مگر خودش میزبان پنل باشد |

نصب افزونه، پنل هیدیفای را نصب یا ارتقا نمی‌دهد. نصب سامانه مرکزی هم افزونه را
از راه دور روی پنل‌ها نصب نمی‌کند. داشتن هفت پنل یعنی نصب افزونه روی هفت میزبان
پنل؛ تعداد سرورهای میانی در این شمارش وارد نمی‌شود.

## نصب سامانه مرکزی

سرور Ubuntu 24.04 یا 26.04 با دسترسی root/sudo و دسترسی خروجی به GitHub و مخازن
بسته‌ها لازم است. دامنه را به IP ورودی سامانه اشاره دهید؛ پورت‌های TCP ۸۰ و ۴۴۳
باید در دسترس باشند. Compose فعلی برای سروری در حدود ۴ گیگابایت RAM طراحی شده؛
فضای دیسک را متناسب با دیتابیس، تصاویر Docker و بکاپ‌ها در نظر بگیرید.

روی **سرور مرکزی** اجرا کنید:

```bash
(set -e; d="$(mktemp -d)"; trap 'rm -rf "$d"' EXIT; cd "$d"; u="https://github.com/Alighaemi9731/hiddify-invoice-system/releases/latest/download"; curl -fsSLO "$u/release-installer.sh"; curl -fsSLO "$u/release-installer.sh.sha256"; sha256sum -c release-installer.sh.sha256; sudo bash release-installer.sh)
```

نصب‌کننده Docker و Compose را در صورت نیاز نصب می‌کند، آرشیو یک Release مشخص
را با SHA-256 بررسی می‌کند، تنظیمات محرمانه را در `.env` می‌سازد و شش سرویس
`db`، `backend`، `scheduler`، `bot`، `frontend` و `caddy` را اجرا می‌کند.
مسیر پیش‌فرض `/opt/hiddify-invoice-system` است. برای نصب Release عمومی، کلون
مخزن یا توکن گیت‌هاب لازم نیست.

در نصب بدون دامنه، آدرس HTTP چاپ‌شده را باز کنید؛ توکن **فعال‌سازی HTTPS**
و دامنه را وارد کنید. بعد در آدرس HTTPS با توکن جداگانه **ساخت حساب**، حساب
مالک را بسازید. توکن ساخت حساب را روی صفحه HTTP وارد نکنید. با تنظیم DNS
و دسترسی درست پورت‌ها، صدور و تمدید گواهی را Caddy انجام می‌دهد.

اگر همان میزبان nginx میانی دارد، پیش از نصب بخش
[هم‌زیستی با relay](../deploy/README.md#co-locating-on-a-tls-passthrough-relay-shares-80443-with-an-nginx-sni-relay)
را بخوانید: نصب‌کننده nginx فعال را تشخیص می‌دهد و دامنه در این حالت لازم است.
قالب `deploy/relay.sh` تنظیمات nginx را بازنویسی می‌کند؛ فقط برای یک relay
اختصاصی با نقشه دامنه‌های بازبینی‌شده از آن استفاده کنید.

## نصب افزونه هر پنل

روی **سرور اصلی هیدیفای** سالم اجرا کنید، نه روی سرور مرکزی یا میانی:

```bash
(set -e; d="$(mktemp -d)"; trap 'rm -rf "$d"' EXIT; cd "$d"; u="https://github.com/Alighaemi9731/hiddify-invoice-system/releases/latest/download"; curl -fsSLO "$u/panel-addon-installer.sh"; curl -fsSLO "$u/panel-addon-installer.sh.sha256"; sha256sum -c panel-addon-installer.sh.sha256; sudo bash panel-addon-installer.sh)
```

نسخه فعال پنل خودکار تشخیص داده می‌شود. پیش از تغییر، بکاپ دیتابیس و فایل‌ها
گرفته می‌شود؛ فقط سرویس `hiddify-panel` برای بارگذاری افزونه ری‌استارت می‌شود.
نتیجه موفق نصب و دستور زیر باید `ready: true` داشته باشد:

```bash
sudo invoice-panel-addon --check
```

همان دستور دانلود، افزونه را به‌روز می‌کند. برای حذف:

```bash
sudo invoice-panel-addon --uninstall
```

جزئیات پیش‌نیازها، محل بکاپ، نسخه مشخص و بازیابی در
[راهنمای افزونه](PANEL_ADDON.md) آمده است. بعد از ارتقای هیدیفای دوباره بررسی
کنید؛ هوک، ارتقای ۱۲.۰.۰ به ۱۴.۲.۰ را تشخیص می‌دهد، ولی نسخه ناشناخته را نمی‌پذیرد.

## راه‌اندازی اولیه و تنظیمات

1. در تنظیمات، مالک تلگرام و توکن بات اصلی را وارد کنید و خودتان بات را `/start`
   کنید تا شناسه عددی مالک ثبت شود. برای عضویت اجباری، دسترسی بات در گروه/کانال را بررسی کنید.
2. **پیش از افزودن و همگام‌سازی داده زنده** تنظیمات وصول را مرور کنید. پیش‌فرض
   فعلی `enforcement_enabled=true` و `registration_enforcement_enabled=true` است؛
   مهلت ثبت‌نام اولیه ۷۲ ساعت است. برای آزمایش محدودسازی بدهی،
   `enforcement_enabled=false` را انتخاب و محدودسازی ثبت‌نام را هم جداگانه بررسی کنید.
   به‌روزرسانی مقدار ذخیره‌شده قبلی این کلیدها را تغییر نمی‌دهد.
3. در پنل‌ها، هر پنل را با لینک مدیریت مالک و اطلاعات API همان پنل اضافه کنید.
   افزونه را روی میزبانش نصب کرده، اتصال و سازگاری را بررسی و سپس همگام‌سازی کنید.
4. نرخ هر گیگ، استثناها، آستانه تست رایگان، روش‌های پرداخت، کیف‌پول/کارت و متن‌ها
   را تنظیم کنید. نرخ اولیه را از تنظیمات خود سامانه بخوانید؛ مقدار محیط نصب می‌تواند
   با پیش‌فرض کد متفاوت باشد.
5. زمان‌بندی همگام‌سازی، صدور ماهانه و بکاپ را تنظیم کنید. وضعیت «اعمال‌شده» را
   در صفحه زمان‌بندی بررسی کنید؛ ذخیره تنظیمات به‌تنهایی اثبات اجرای worker نیست.
6. یک دوره را تولید و پیش‌نویس‌ها را بازبینی کنید. **صدور بدهی با ارسال تلگرام
   متفاوت است**؛ پیش از صدور، دوره، مبلغ و سیاست وصول را بررسی کنید.

## امکانات و قواعد مالی

| بخش | رفتار |
|---|---|
| محاسبه ماهانه | سهمیه فروخته‌شده سرویس‌های دوره میلادی، با تجمیع زیرمجموعه نماینده؛ قیمت اختصاصی، معافیت و آستانه تست قابل تنظیم |
| تشخیص مصرف و تمدید | شمارنده تجمعی مقاوم به reset و ثبت اقلام اضافه برای مصرف/ویرایش سهمیه طبق سیاست metering |
| فاکتور | پیش‌نویس، صدور، PDF فارسی، مهلت پرداخت، لغو و گزارش؛ فاکتور پرداخت‌شده در تولید مجدد محاسبه نمی‌شود |
| پرداخت | USDT روی BEP-20، TON، AVAX و کارت‌به‌کارت با فعال‌سازی جداگانه هر روش |
| تأیید پرداخت | TXID تازه و منطبق می‌تواند طبق تنظیمات خودکار تأیید شود؛ تصویر رسید و کارت‌به‌کارت بررسی دستی دارند |
| وصول | یادآوری‌های روز ۳ و ۵، اخطار روز ۱۰ و محدودسازی روز ۳۰ به‌صورت پیش‌فرض؛ قابل تنظیم |
| دسترسی نماینده | محدودسازی و بازگردانی صف‌دار، بازیابی سقف‌های قبلی و ورود بدون رمز با افزونه؛ freeze برای توقف ایجاد/افزایش بدون قطع کاربران موجود |
| پنل مالک | داشبورد، نمایندگان و درخت زیرمجموعه، بدهی و فروش، دفتر مالی، پیگیری نمایندگان، لاگ، ابزارها و بکاپ |
| بات و پرتال | ثبت‌نام با لینک پنل، فاکتور و پرداخت، مدیریت زیرمجموعه و ورود یک‌بارمصرف به پرتال فارسی |
| فروشگاه نماینده | بات مستقل، طرح فروش، کیف‌پول، شارژ، کد اعتبار، ساخت/تمدید، تست و QR؛ مدیریت از بات و پرتال |
| پیام هدفمند | فیلتر بدهی/پنل/دوره/دسترسی، پیش‌نمایش مخاطبان و CSV؛ [راهنما](BROADCAST.md) |

مهلت وصول از صدور شروع می‌شود، حتی اگر ارسال تلگرام شکست بخورد یا نماینده هنوز
ثبت‌نام نکرده باشد. وضعیت مالی، وضعیت تحویل و محدودیت دسترسی را جدا بررسی کنید.
دادن مهلت جدید، مبنای وصول همان فاکتور را تغییر می‌دهد. دفتر مالی مستقل برای
نگهداری سابقه پولی است؛ حذف پنل راه جابه‌جایی آن به سرور تازه نیست.

## تغییر IP یا جابه‌جایی سرور هیدیفای

اگر دامنه، مسیرهای مخفی و UUIDها حفظ شده‌اند، رکورد **همان پنل** در سامانه را
نگه دارید. حذف و ایجاد دوباره پنل می‌تواند هویت مالی و اتصال نمایندگان را به هم بزند.

1. برای انتقال برنامه‌ریزی‌شده، پنل را در maintenance قرار دهید تا عملیات همان
   پنل متوقف و کارهای در جریان تخلیه شوند؛ از هیدیفای و سامانه بکاپ بگیرید.
2. پنل و داده‌ها را روی میزبان جدید بازیابی و سلامت هیدیفای را تأیید کنید.
3. اگر دامنه مستقیم است، DNS را به میزبان تازه اشاره دهید. اگر سرور میانی دارید،
   DNS به میانی اشاره می‌کند و مسیر میانی باید به **IP اصلی جدید** برسد؛ TLS باید
   با دامنه واقعی معتبر بماند. افزونه را روی مقصد اصلی نصب کنید.
4. اگر خود دامنه/مسیر/UUID عوض شده، همان رکورد پنل را ویرایش کنید. alias دامنه
   قدیمی فقط برای تشخیص لینک‌های قدیمی بات است و مسیر اتصال API را تغییر نمی‌دهد.
5. روی مقصد `invoice-panel-addon --check` و از سامانه preflight خواندنی را اجرا کنید.
   شناسه پنل را از فهرست/API بگیرید؛ شماره نمایشی سرور لزوماً شناسه دیتابیس نیست.

```bash
cd /opt/hiddify-invoice-system
docker compose --env-file .env -f deploy/docker-compose.prod.yml exec -T backend \
  python -m app.services.panel_preflight --panel-id PANEL_ID
```

در نسخه ۱۲، نتیجه `legacy_hook_required` یعنی بررسی محلی افزونه هم لازم است.
در نسخه ۱۴، قابلیت افزونه از API بررسی می‌شود. preflight خواندنی، آزمون کامل
قطع/وصل کاربران یا VPN نیست. خروج از maintenance، preflight و همگام‌سازی تازه
را الزام می‌کند؛ [راهنمای ارتقا](HIDDIFY_UPGRADE.md) و
[قرارداد سازگاری](HIDDIFY_COMPATIBILITY.md) جزئیات را دارند.

## به‌روزرسانی و بازگشت

پیش از به‌روزرسانی، از «حساب و پشتیبان‌گیری» بکاپ تازه بگیرید و نسخه فعلی را ثبت
کنید. دستور نصب مرکزی را دوباره اجرا کنید یا از مسیر نصب:

```bash
cd /opt/hiddify-invoice-system
sudo bash deploy/release-installer.sh
bash deploy/smoke.sh
cat VERSION .deployed-release
docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
```

نصب‌کننده تنظیمات و volume دیتابیس را نگه می‌دارد؛ بازسازی و راه‌اندازی سرویس‌ها
وقفه کوتاه ایجاد می‌کند. افزونه پنل‌ها مستقل است و با آپدیت مرکزی خودکار آپدیت
نمی‌شود. Release و checksum آن در `update/releases` برای بازگشت نگه‌داری می‌شوند:

```bash
sudo bash deploy/rollback.sh vX.Y.Z
```

برچسب واقعی قبلی را جایگزین کنید. اگر migration تازه‌ای وجود دارد، بازگشت صرف کد
متوقف می‌شود؛ دستور `ALLOW_DOWNGRADE` را فقط پس از بررسی سازگاری داده در
[فرایند انتشار و بازگشت](RELEASE_PROCESS.md) اجرا کنید.

## بکاپ و بازیابی

بکاپ دوره‌ای و درخواست دستی از رابط مالک در دسترس است؛ فاصله پیش‌فرض ۲ ساعت
است و از تنظیمات تغییر می‌کند. تحویل خودکار به تلگرام به توکن درست و ثبت مالک
وابسته است. آخرین تحویل موفق را بررسی و یک نسخه خارج از سرور نگه دارید.

آرشیو شامل دیتابیس و اطلاعات لازم رمزگشایی تنظیمات است و محرمانه محسوب می‌شود.
با `backup_passphrase` می‌توانید رمزگذاری آرشیو را فعال کنید؛ عبارت عبور را خارج
از سامانه نگه دارید. فایل `.env` و کلیدها را عمومی نکنید. بازیابی از رابط، دیتابیس
را اتمیک اعمال و فرایندهای برنامه، زمان‌بند و بات را با سیگنال مشترک راه‌اندازی
مجدد می‌کند تا اتصال دیتابیس و تنظیمات بازیابی‌شده را تازه بخوانند.
در بازیابی دستی طبق [راهنمای دیتابیس](DATABASE.md) عمل کنید. از `down -v`
برای نگهداری عادی استفاده نکنید؛ volumeها را حذف می‌کند.

## بررسی سلامت و عیب‌یابی

دستورهای زیر روی سرور مرکزی و از پوشه نصب اجرا می‌شوند:

```bash
cd /opt/hiddify-invoice-system
docker compose --env-file .env -f deploy/docker-compose.prod.yml ps
docker compose --env-file .env -f deploy/docker-compose.prod.yml logs --since=10m backend scheduler bot
systemctl is-active hiddify-updater
systemctl is-active hiddify-healthwatch.timer
bash deploy/smoke.sh
```

| نشانه | بررسی بعدی |
|---|---|
| دامنه باز نمی‌شود | DNS، پورت‌های ۸۰/۴۴۳، TLS و مسیر میانی به اصلی |
| خطای اتصال پنل | لینک/کلید مالک، دامنه و مسیر مخفی، آخرین sync و preflight |
| افزونه آماده نیست | روی میزبان اصلی `invoice-panel-addon --check` و `journalctl -u hiddify-panel.service -n 80 --no-pager` |
| فاکتور در تلگرام نرسیده | وضعیت صدور و تحویل را جدا ببینید؛ ثبت‌نام نماینده، توکن بات، مسدود بودن بات و لاگ تحویل |
| پرداخت هنوز pending است | شبکه، مقصد، مبلغ، تازگی و تأییدهای TXID یا نیاز به بررسی دستی |
| تنظیم زمان‌بندی اعمال نشده | وضعیت saved/applied، سلامت `scheduler` و خطاهای همان سرویس |
| بات پاسخ نمی‌دهد | توکن، دسترسی تلگرام، سلامت `bot` و نمونه دوم polling با همان توکن |

وضعیت `/health` شامل دیتابیس، heartbeat زمان‌بند و ناوگان فروشگاه است؛ صرف بالا
بودن صفحه ورود، اجرای کارهای پس‌زمینه را ثابت نمی‌کند. راهنمای
[پایش و هشدار](MONITORING.md) روش پیگیری خطاها را توضیح می‌دهد. خروجی لاگ‌ها را
پیش از اشتراک از نظر لینک مخفی، UUID، توکن و داده کاربران بررسی کنید.
